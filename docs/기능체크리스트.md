#### API

| 기능 | 상태 | 파일 |
|---|---|---|
| `POST /api/auth/signup` — 이메일 정규식 + 8자 검증 | ✅ | `app/api/auth/signup/route.ts` |
| 중복 이메일 사전 조회 → `EMAIL_TAKEN` 400 | ✅ | 유니크 제약 위반을 500으로 흘리지 않는다 |
| scrypt 해시 저장, `cognitoSub = local:<uuid>` | ✅ | 평문·복호화 가능 형태 저장 0건 |

| Cognito 경로 (`USER_PASSWORD_AUTH`) 폴백 | ✅ | Google 계정은 `passwordHash`가 `null`이라 이쪽으로 내려간다 |
| 실패 문구를 하나로 통일 (계정 존재 여부 비노출) | ✅ | `NotAuthorized`·`UserNotFound` 둘 다 같은 401 문구 |
| `POST /api/auth/logout` — 쿠키 2개 삭제 + `/login` | ✅ | POST 전용(GET으로 열면 405) |

| `GET /api/auth/callback` — code → 토큰 교환 | 🔧 | `state` 대조 후 쿠키 삭제(CSRF). 실패 사유를 CloudWatch에 남기되 `code`는 안 남긴다 |
| **모든 로그인 경로가 자체 세션 쿠키(7일)** | ✅ | Cognito 액세스 토큰(1시간, refresh 없음)을 쿠키에 담지 않는다. `signInWithCognitoToken()` 경유(2026-08-22) |
| 미설정 시 503 + "이메일로 로그인해 주세요" 안내 | ✅ | `COGNITO_DOMAIN`이 비어 있어도 500이 아니다 |

## 3. 명세와 구현이 갈린 항목 (발표 전 정리 필요)

1. **진단 문항 6개 → 13개 + 조기 종료.** 의도적 결정(결정 변경 3번)인데 `SPEC.md` 3절이 6개로 남아 있다. 심사에서 문서와 화면이 어긋난다
2. **진단 LLM 2종 컷.** 지금 진단의 LLM은 결과 근거 3줄 하나뿐이다. "LLM은 문장 생성과 enum 변환만" 이라는 13절 답변을 근거 3줄 기준으로 고쳐야 한다
3. **커뮤니티 주제 추천이 LLM이 아니다.** 정적 상수다
4. **희망 문구 배너 미구현.** 상수 3~5개 + 배너 한 장이라 30분 작업
5. **7일 streak 별조각 보너스 미구현.** 수급표(63.6/일)는 이걸 안 넣어도 성립한다(별조각 60 완주 보너스가 대부분) — 넣지 않고 명세를 고치는 쪽이 싸다

## 4. 가장 초기 기획(`아이디어.md`) 대비 미구현

`아이디어.md`는 기능 블록 6개로 시작했다. `SPEC.md` 확정 과정에서 잘려나간 것을 여기 따로 모은다 — 아래 항목은 "버그"가 아니라 **초기 기획에는 있었는데 지금 서비스에 없는 것**이다.

|---|---|---|---|
| 1 | 유형 분류 — **아키네이터(LLM 활용) 대화형 진단** | ⚠️ | 판정은 코드가 하고 **LLM은 진단 과정에서 한 번도 안 돈다.** 남은 LLM은 결과 근거 3줄뿐이다. "대화형"도 실제로는 선택지 버튼이고 자유 입력 → enum 변환은 컷됐다 |
