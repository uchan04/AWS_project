# 공유 DB와 사고 3건 — 비개발자를 위한 설명

대상: A~E 전원. 특히 Prisma 명령을 외워서 쓰고 있는 사람.
읽는 시간: 8분. **이 문서에 나오는 사고 3건은 전부 이 프로젝트에서 실제로 일어났다.**

---

## 0. 30초 요약

`git pull` 뒤에는 **항상** 이 두 줄까지가 한 동작이다.

```bash
npx prisma migrate deploy && npx prisma generate
```

이걸 안 해서 `develop`이 한때 **로그인부터 전면 500**이었다.

---

## 1. 창고 비유 — DB가 무엇인가

**DB(데이터베이스)는 팀 공용 창고다.** 서랍장이 줄지어 있고, 서랍마다 이름표가 붙어 있다.

| 창고의 것 | 실제 이름 | 예 |
|---|---|---|
| 서랍장 하나 | 테이블(table) | `User`, `Mission`, `Post` |
| 서랍장의 칸 | 컬럼(column) | `User.email`, `User.isAdmin` |
| 칸에 든 물건 하나 | 행(row) | 사용자 한 명, 미션 한 개 |
| 서랍장 설계도 | `prisma/schema.prisma` | 이 파일이 "어떤 칸이 있어야 하는가"를 적는다 |

여기서 **가장 중요한 사실** 하나.

> `schema.prisma`를 고치는 것은 **설계도에 연필로 칸을 그리는 것**이다.
> 실제 창고에 칸이 파이는 것은 아니다.

설계도와 실제 창고는 **따로** 움직인다. 이 두 개가 어긋나면 사고가 난다. 아래 사고 3건이 전부 그 어긋남이다.

---

## 2. Prisma 명령 5개의 정체

| 명령 | 창고 비유 | 누가 | 공유 DB에 |
|---|---|---|---|
| `npx prisma migrate dev` | 설계도를 보고 **실제로 칸을 판다** + 그 공사 지시서를 새로 쓴다 | **스키마 담당 1인만** | **금지** |
| `npx prisma migrate deploy` | 남이 써 둔 공사 지시서를 **내 창고에 그대로 적용**한다 | 전원, `git pull`마다 | 이것만 허용 |
| `npx prisma generate` | 창고 칸 이름을 **코드가 읽을 수 있게 인쇄**한다 | 전원, `deploy` 직후 | DB를 건드리지 않는다 |
| `npm run db:seed` | 서랍 **내용물**을 표준값으로 덮어쓴다 (미션 909행, 상점 아이템) | 지시받은 1인 | 승인 필요 |
| `npx prisma migrate reset` | **창고를 비운다.** 전부. | 아무도 | **절대 금지** |

`migrate dev`와 `migrate deploy`가 이름이 비슷해서 헷갈린다. 차이는 하나다.

- `dev` = **지시서를 만든다** (설계도가 바뀐 사람이 쓴다)
- `deploy` = **지시서를 실행한다** (설계도를 안 바꾼 사람이 쓴다)

여러 명이 `dev`를 각자 돌리면 지시서가 여러 갈래로 갈라진다. 갈라진 지시서는 합칠 수 없다 — 순서가 다르면 같은 칸을 두 번 파려고 하거나, 없는 칸을 지우려고 한다.

## 3. 사고 1 — 코드가 창고보다 앞섰다 (로그인 전면 500)

**언제**: 2026-08-24, `develop` 브랜치
**증상**: 로그인부터 안 됐다. 로그인·홈·펫·미션·커뮤니티 — **다섯 화면 전부** 500.
**처음 나온 보고**: "모임 기능이 안 돼요"

### 무슨 일이 있었나

D가 모임(Meetup) 기능을 만들면서 설계도에 칸 하나를 새로 그렸다 — `User.isAdmin`. 코드도 그 칸을 읽게 고쳤고, 커밋해서 `develop`에 올렸다.

**그런데 공유 창고에는 그 칸이 안 파여 있었다.** 지시서(마이그레이션 파일)는 커밋에 들어갔지만, 실행하는 건 아무도 안 했다.

그래서 Prisma가 이렇게 죽었다.

```
P2022: The column `User.isAdmin` does not exist in the current database.
```

### 왜 모임만이 아니라 전부 죽었나

이게 이 사고의 핵심이다. `getCurrentUser()`가 사용자 한 명을 읽을 때 이렇게 한다.

```ts
prisma.user.findUnique({ where: { id } })   // 컬럼을 골라 읽지 않는다 = 전부 읽는다
```

`select`를 안 쓰면 Prisma는 **설계도에 적힌 모든 칸을 읽는다.** 그중 하나가 창고에 없으면 쿼리 전체가 죽는다. 그리고 `getCurrentUser()`는 **모든 API의 첫 줄**이다(CLAUDE.md 2절).

> 칸 하나가 없으면 → 사용자 조회가 죽고 → 인증이 죽고 → 전부 죽는다.

"모임 기능이 안 된다"는 보고가 실제로는 "인증이 죽었다"였던 이유다.

### 고친 방법

누군가 `npx prisma migrate deploy`를 돌렸다. 끝. **코드는 한 줄도 안 고쳤다.**

### 배운 것

1. **스키마 변경은 `main` 머지 *전에* 공유 DB에 적용한다.** 순서가 반대면 배포본이 죽는다.
2. **`git pull` 뒤에는 `migrate deploy && generate`까지가 한 동작이다.**
3. **"기능 하나가 안 된다"가 "전부 안 된다"일 수 있다.** 화면 하나만 보고 원인을 좁히지 않는다. 로그인을 먼저 해 본다.

## 4. 사고 2 — 창고가 내 코드보다 앞섰다 (덮어쓸 뻔했다)

**언제**: 2026-08-24, `npm run db:seed`를 돌리기 직전
**증상**: 없었다. 돌리기 전에 발견했다.

### 무슨 일이 있었나

미션 배치를 고쳐서 공유 DB에 반영해야 했다. `db:seed`는 시드 파일을 읽어 창고 내용물을 **덮어쓴다**(upsert).

그런데 그 사이에 다른 담당이 `PetSkin.avatarKey`에 값을 채워 넣었고, **내 체크아웃의 시드 파일에는 그 값이 없었다.** 그 상태로 `db:seed`를 돌리면 upsert가 `avatarKey`를 빈 값으로 덮어쓴다.

### 왜 위험한가

`db:seed`는 "빠진 것만 채우는" 명령이 아니다. **표준값으로 맞추는** 명령이다. 내 시드 파일이 낡았으면 창고를 낡은 상태로 되돌린다.

### 고친 방법

`git pull`로 팀 커밋을 먼저 받고, 시드 파일이 최신인 걸 확인한 뒤에 돌렸다. 결과: **신규 0 / 갱신 534**. `Mission` 909행 중 534행의 배치가 갱신됐고, 다른 건 안 건드렸다.

돌리기 전에 `prisma/_backup-missions.json`에 914행을 떠 놓았다.

### 배운 것

1. **`db:seed` 전에 `git pull`.** 예외 없다.
2. **`db:seed` 전에 되돌릴 수 있게 백업을 뜬다.** 공유 DB 쓰기는 되돌릴 방법을 먼저 만든 뒤에 한다.

## 5. 사고 3 — 자체 검사 9종이 전부 통과했는데 500이었다

**언제**: 2026-08-23~24
**증상**: 로그인 안 한 사람이 `/pet`을 열면 500.
**범인**: 나(A). 내가 낸 회귀다.

### 무슨 일이 있었나

로그인 안 한 사람을 `/login`으로 보내는 코드(`middleware.ts`)에서 이렇게 썼다.

```ts
// 이게 500을 냈다
return NextResponse.redirect("/login?next=/pet")
```

**미들웨어의 리다이렉트 주소는 반드시 전체 주소여야 한다.** Next가 이 값을 `new URL()`로 해석하는데, `/login`처럼 앞이 잘린 주소는 `new URL()`이 못 읽는다.

```
TypeError: Invalid URL   code: ERR_INVALID_URL   input: '/login?next=%2Fpet'
```

고친 형태:

```ts
const login = new URL("/login", appOrigin(request))  // https://…/login
login.searchParams.set("next", `${pathname}${search}`)
return NextResponse.redirect(login, 307)
```

### 헷갈리는 지점 — 규칙이 두 개다

| 어디서 | 상대 경로(`/login`) | 왜 |
|---|---|---|
| `middleware.ts` | **안 된다** | Next의 Edge 어댑터가 `new URL()`로 해석한다 |
| API 라우트(`app/api/…/route.ts`) | **된다** | 평범한 `Response`라 브라우저가 알아서 붙인다 |

같은 리다이렉트인데 파일 위치에 따라 규칙이 다르다. `lib/oauth.ts`의 `appRedirect()`가 상대 경로를 쓰고 잘 도는 걸 보고 미들웨어도 되는 줄 알았다.

### 왜 못 잡았나 — 이게 진짜 배울 점

```
npm run check:auth, check:pet, check:missions, … 9종   →  전부 통과 ✅
npm run e2e                                            →  실패 1건 ❌  ← 이것만 잡았다
```

`check:*`는 **순수 함수**를 단정한다. 함수에 값을 넣고 나온 값을 확인한다. 이 경로를 지나지 않는다.
`npm run e2e`는 **실제 서버에 요청을 보낸다.** 로그인 안 한 상태로 `/pet`을 요청하는 건 e2e만 한다.

> **미들웨어·인증·커뮤니티 라우트를 만졌으면 `npm run e2e`를 함께 돌린다.**

e2e는 **서버가 떠 있어야 한다.** 안 켜면 `ECONNREFUSED`로 죽는다. 커넥션 아끼려고 서버를 끈 상태에서 돌리면 이걸 본다.

### 곁가지 — CSP도 같은 계열로 한 번 더 터졌다

펫 그림이 전부 안 나온 적이 있다. `tsc`·`lint`·`build`·`check:*` 전부 통과했다. **브라우저를 열어야만 보이는 문제**였다.

원인: 보안 헤더(CSP)의 `img-src`에 CloudFront 주소가 없어서 브라우저가 그림을 전부 차단했다. 서버는 200을 잘 돌려줬다 — 브라우저가 버린 것이다.

> **화면 결과물(그림·글꼴·외부 요청)은 브라우저를 열어야 확인된다.** 빌드 통과는 화면 통과가 아니다.

## 6. 커넥션 — 왜 시연 전에 서버를 끄라고 하나

DB에는 **동시에 말을 걸 수 있는 창구 수**가 정해져 있다.

```
우리 RDS의 창구 수                       79개
  − 관리자 예약                           3개
────────────────────────────────────
  앱이 쓸 수 있는 것                     76개

로컬 서버 1대가 잡는 창구 (Prisma 기본값)  25개   ← CPU 12개 × 2 + 1
5인이 각자 로컬 서버를 켜면              125개   ← 76개보다 많다
```

**5명이 다 켜면 배포본 몫이 0이 된다.** 그러면 시연 중에 배포본이 DB에 접속을 못 한다.

그리고 Prisma는 **한 번 연 창구를 프로세스가 죽을 때까지 안 닫는다.** 실측: 부하를 주니 11개 → 23개로 늘었고, 부하가 끝난 뒤에도 23개에서 안 줄었다.

> **"서버종료"는 프로세스만 죽이는 게 아니라 커넥션 반납까지다.** 창을 닫는 것으로는 안 된다 — 프로세스를 끝내야 창구가 돌아온다.

시연 전 체크: **5인 전원 로컬 서버 종료.**

남은 조치(E 담당): Amplify의 `DATABASE_URL`에 `connection_limit=2`를 붙이고 재배포. 배포본이 25개씩 잡는 걸 2개로 줄인다.

## 7. 증상 → 원인 표 (막혔을 때 여기부터)

| 증상 | 가장 흔한 원인 | 먼저 해 볼 것 |
|---|---|---|
| 로그인부터 500 | 마이그레이션 미적용 | `npx prisma migrate deploy && npx prisma generate` |
| `P2022 … does not exist` | 같음 | 같음 |
| 타입 에러: 그 필드 없다는데 코드엔 있다 | `generate` 안 함 | `npx prisma generate` |
| 로그인 **안 한** 상태에서만 500 | 미들웨어 리다이렉트 | `middleware.ts`의 `Location`이 전체 주소인지 |
| 그림이 안 나온다 (서버는 200) | CSP `img-src` | 브라우저 콘솔에서 `Refused to load` 확인 |
| `ECONNREFUSED` | 서버 안 켰다 | `preview_start` 또는 `npm run dev` |
| DB 접속이 안 된다 / 느리다 | 커넥션 79개 소진 | 팀 전원 로컬 서버 종료 |
| 빌드가 깨진다 | `DEV_AUTH_BYPASS=true` | `.env`에서 끄고 다시 빌드 |

## 8. 절대 하지 않는 것 4개

1. `npx prisma migrate reset` — 공유 창고를 비운다
2. `npx prisma migrate dev`를 공유 DB에 — 지시서가 갈라진다
3. 공유 브랜치에 `--force` push — 남의 커밋을 지운다
4. `rebase` — 충돌이 커밋마다 반복돼 되돌릴 수 없다
