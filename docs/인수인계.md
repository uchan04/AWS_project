## 1. 무엇을 만드는가

고립·은둔 상태의 청년이 **자기 유형을 진단받고, 그 유형에 맞는 작은 미션을 수행하며, 펫을 키우고 같은 유형끼리 모인 익명 커뮤니티에서 이야기하는** 서비스다.

핵심 설계 의도 세 가지만 기억하면 된다.

1. **낙인을 만들지 않는다.** 내부 유형 이름("건강·정서취약형" 등)은 화면에 절대 노출하지 않는다. 사용자에게는 종족·동물(여우 / 고양이 / 곰)로만 보여준다.
2. **경쟁을 만들지 않는다.** 랭킹, 순위, 남과 비교되는 지표는 의도적으로 넣지 않는다.
3. **LLM은 판정하지 않는다.** 유형 판정은 100% 코드가 계산한다. LLM은 질문 문장을 다듬고 자유 답변을 선택지로 변환하는 데만 쓴다. 이렇게 하면 환각으로 잘못된 진단이 나오는 일이 구조적으로 불가능하다.

기술 스택: Next.js (App Router, TypeScript) / Prisma + RDS Postgres / Cognito / Bedrock Claude Sonnet / S3 / AWS Amplify Hosting.

## 3. 애로사항 (중요도 순)

### 3-1. DB가 없다 — 전원 차단, 최우선

`DATABASE_URL`이 비어 있고 `prisma/migrations/` 폴더가 없다. 결과:

- clone 후 `npx prisma migrate deploy`가 실패한다
- 모든 API의 첫 줄이 `getCurrentUser()`이고 이 함수가 DB에 유저를 만드는 구조여서, **DB 없이는 API가 한 개도 안 돈다**
- 정적인 화면(데이터 없는 UI)만 만들 수 있다

**해결**: 인프라 담당이 RDS Postgres `db.t4g.micro`를 만들고 `DATABASE_URL`을 받아 `npx prisma migrate dev --name init`을 **한 번만** 실행해 마이그레이션 파일을 커밋한다. 그 후 나머지 4명에게 `DATABASE_URL`을 공유한다. 이것이 8/15 오전에 끝나야 한다.

임시 우회로: 로컬에 Postgres를 설치해도 되지만, 5명이 각자 설치하면 설치 문제로 반나절이 날아갈 수 있다. RDS 하나를 공유하는 쪽이 빠르다.

### 3-2. 로그인이 없다

Cognito 사용자 풀이 아직 없다. 개발 중에는 `.env`에 `DEV_AUTH_BYPASS=true`를 넣으면 고정된 개발용 계정으로 자동 로그인된 것처럼 동작한다. 실제 로그인·회원가입 화면과 Cognito 토큰 검증은 인프라 담당이 8/16까지 붙인다.

> **주의**: `DEV_AUTH_BYPASS`는 배포 환경에서 절대 `true`로 두지 않는다. 누구나 같은 계정으로 들어오게 된다.

### 3-3. 미션 콘텐츠 41개가 6개뿐이다

일일 5개와 예시 1개만 초안 상태다. 유형별 12개 × 3유형 = 36개가 비어 있다. 미션이 없으면 미션 시스템·펫·보상이 전부 빈 화면이 된다. 진단 담당이 연구보고서 PDF를 근거로 8/16까지 채우고 전원이 15분 검수한다.

### 3-4. 화면 디자인 기준이 없다

전역 레이아웃·하단 탭 내비게이션·색 토큰이 비어 있다. 5명이 각자 버튼과 카드를 만들면 발표 화면이 통일감 없이 보인다. 인프라 담당이 `app/layout.tsx`에 하단 탭 내비게이션과 색 토큰을 한 번 넣고 **동결**한다. 그 뒤로는 아무도 이 파일을 고치지 않는다.

### 3-5. 일정이 하루 밀렸다

원래 8/14에 끝나야 했던 인프라 착수가 8/15로 넘어왔다. 남은 개발일은 8일이고 총 작업량은 약 15인일이다. 여유가 거의 없다. **8/19 중간 체크포인트에서 미완성 항목이 3개를 넘으면 `업무분담.md` 4절의 컷 순서를 그날 즉시 발동한다. 그 자리에서 토론하지 않는다.**

컷 순서: ① 커뮤니티 LLM 주제 추천 → ② 캐릭터 고유 효과를 씨앗 1종으로 축소 → ③ 방치형 자동 획득 → ④ 출석 7일 캘린더

## 4. 받고 나서 해야 할 일

### 4-1. 전원 공통 (30분)

```bash
git clone https://github.com/uchan04/AWS_project.git
cd AWS_project
npm install
cp .env.example .env
```

`.env`를 열어 인프라 담당이 공유한 `DATABASE_URL`을 채우고, `DEV_AUTH_BYPASS=true`를 넣는다. 그다음:

```bash
npx prisma migrate deploy
npx prisma generate
npm run dev
```

http://localhost:3000 이 열리면 세팅 완료다. 마지막으로 자기 브랜치를 만든다.

```bash
git checkout -b feat/<자기 브랜치 이름>
```

브랜치 이름은 4-3의 표에 있다.

### 4-2. 담당별 첫 작업

각자 `docs/dev/<기능>.md`에 자기 진행 상황을 적어가며 일한다. 세부 산출물 목록은 `업무분담.md` 1장에 있다.

**A — 유형 진단 + 미션 콘텐츠** (`feat/diagnosis`, `app/diagnosis/`, `/api/diagnosis/*`)

1. 진단 6문항을 문항 코드·선택지·axis·weight로 확정한다 (`SPEC.md` 3절)
2. 판정 함수 `답변 배열 → { typeCode, adjective, axisScores }`를 만든다. **LLM을 쓰지 않는다.** 순수 계산 함수다
3. 미션 41개를 `prisma/seed/missions.ts`에 채운다 — 8/16까지, 최우선
4. 결과 화면과 닉네임 변경 UI

**B — 미션 시스템 + 사진 업로드** (`feat/missions`, `app/missions/`, `/api/missions/*`, `/api/upload/*`)

1. 일일 미션 목록 화면. 미션 데이터가 6개뿐이어도 화면은 먼저 만들 수 있다
2. 완료 처리 API. 중복 방지는 DB 유니크 제약이 하므로 코드에서 중복 체크를 따로 하지 않는다
3. 단계 미션 잠금·해제 (앞 단계 4개 중 3개 완료 시 해제)
4. 사진 업로드는 S3 버킷이 생긴 뒤에 착수한다

**C — 펫** (`feat/pet`, `app/pet/`, `/api/pet/*`)

1. `lib/reward.ts`를 먼저 확인·확정한다. **4명이 이 함수를 기다린다.** 시그니처를 바꾸려면 전원에게 알린다
2. 펫 화면: 레벨·경험치·씨앗 투입·진화 연출 (**씨앗 1 = 경험치 10**, 필요 경험치 = 레벨 × 100, 5레벨에 2단, 15레벨에 3단)
3. 방치형 자동 획득: 씨앗 시간당 2개, 상한 12시간분. 획득이므로 `calculateReward()`를 통과한다
4. 치장 착용은 슬롯당 1개다. 도감 화면을 따로 만들지 않고 목록의 수집 진행률로 겸용한다
5. **화폐는 상점별로 전용이다 (2026-08-20 확정).** 스킨은 별조각만, 치장은 친밀도만 받는다
   - **종족 외형 스킨 3종** (북극여우·북극고양이·북극곰): 별조각 **2500**. **자기 종족만** 살 수 있다(남의 종족을 사면 진단 결과와 어긋난 동물이 뜬다). 능력치 효과는 없고 외형만 바뀐다
   - **치장 배경 6종** (`배경1`~`배경6`): 친밀도, 등급에서 파생 — 6종 전부 COMMON = 각 **600**(합 3600). 종족 구분이 없어 누구나 산다. 2026-08-20에 12종(모자·목도리·배경)에서 배경만 남겼다(이미지 제작 시간). `Slot` enum의 `HAT`·`SCARF`는 스키마에 그대로 있다
   - 가격의 유일한 출처는 `prisma/seed/items.ts`다(`VARIANT_PRICE_SHARDS`, `PRICE_BY_RARITY`). **아이템을 추가할 때 가격을 손으로 적지 않는다** — 등급만 정하면 파생된다
   - 구매는 소비이므로 `calculateReward()`를 **통과하지 않는다.** 배율을 얹으면 60짜리를 살 때 69가 빠진다
6. **가챠는 컷이다 (2026-08-19 팀 결정).** 확률·천장·중복 환급·`GachaPull`을 전부 뺐다. 되살릴 일이 생기면 `git show 7b0bcd0`에 제거분 전체가 있다
7. **재화 수급량도 확정됐다 (2026-08-20).** 일일 미션 전체 완료 = 별조각 60 / 글 작성 = 친밀도 20, 일 상한 100. 수급은 별조각 약 63.6/일 · 친밀도 최대 100/일이라 스킨 39일 · 배경 전부 36일이다. 두 상점 속도를 맞춘 값이고, 8/26 녹화는 데모 계정에 재화를 시드로 심어 찍는다
   - **별조각 60은 아직 구현되지 않았다** — `lib/missions/completion.ts:128` TODO(B 담당). 없으면 수급이 출석 3.6/일뿐이고 스킨 2500이 약 700일이다
   - **실 DB 반영은 끝났다** (2026-08-20 `npm run db:seed`). 스킨 3종 = 2500, 치장은 옛 12행이 삭제되고 `배경1`~`배경6` = 각 600만 남았다(보유자가 0이라 전부 지워졌다. 보유자 있는 행은 지우지 않고 경고만 찍는다). 시드 파일과 실 DB가 일치하므로 어긋나게 두지 않는다

**D — 커뮤니티 + 챗봇** (`feat/community`, `app/community/`, `/api/community/*`, `/api/chat/*`)

1. 유형별 갤러리 3개: 목록 → 상세 → 글쓰기 → 댓글 → 좋아요 → 본인 글 삭제
2. 작성자 표기는 `닉네임 + 종족 배지` 형식 (예: "조용한 고양이 · 고양잇과"). `lib/types.ts`의 `authorLabel()`을 쓴다
3. AI 챗봇: **시스템 프롬프트에 "조언과 해결책을 제시하지 말고 공감과 경청에 집중"을 반드시 명시한다.** 이 서비스에서 챗봇이 해결책을 들이대면 역효과다
4. 친밀도 지급 — 챗봇 1턴 5 / 글 20 / 댓글 5, **하루 누계 상한 100 공유**

**E — 인프라 + 인증 + 발표 자료** (`feat/infra`, `app/(auth)/`, `/api/auth/*`)

| E | | 인프라 + 인증 + 발표 | `feat/infra` | `app/(auth)/` | `/api/auth/*` |

분담 방식은 **기능 수직 분할**이다. 한 사람이 하나의 기능을 화면부터 API, DB까지 관통한다. 프론트/백으로 나누면 모든 기능이 두 명을 거쳐야 끝나서 8일 안에 못 끝낸다.

## 5. 반드시 지켜야 할 규칙 7개

이 7개만 지켜도 합병 사고는 거의 안 난다. 전문은 `CLAUDE.md`에 있다.

**1. 재화 증감은 `calculateReward()`만 통과한다.**

```ts
// 금지
user.seeds += 10

// 필수
const reward = calculateReward(user.activePetSkin, { seeds: 10 })
```

캐릭터 고유 효과(씨앗 +15% 등)가 이 함수 안에만 있다. 직접 증감하면 배율이 빠지거나 이중으로 적용된다.

**2. 남의 폴더를 건드리지 않는다.** 다른 사람 폴더에서 버그를 발견하면 고치지 말고 알린다.

**3. 공유 파일은 기능 브랜치에서 고치지 않는다.** 아래 파일은 5명이 전부 의존한다. 변경이 필요하면 소유자에게 요청하고, 소유자가 `main`에 직접 커밋한 뒤 전원에게 알린다.

| 파일 | 소유자 |
|---|---|
| `prisma/schema.prisma` | 전원 합의 |
| `lib/auth.ts` | E |
| `lib/reward.ts` | C |
| `lib/types.ts` | A |
| `app/layout.tsx`, `app/globals.css` | E |
| `.env.example` | E |
| `prisma/seed/missions.ts` | A |
| `prisma/seed/items.ts` | C |

**4. `npx prisma migrate dev`는 스키마 담당 1인만 실행한다.** 여러 명이 각자 실행하면 마이그레이션 히스토리가 갈라져 병합이 불가능해진다. 나머지는 스키마 변경 공지를 받으면 `git pull && npx prisma migrate deploy && npx prisma generate`만 실행한다.

**`npx prisma migrate reset`은 절대 실행하지 않는다.** 공유 DB의 모든 데이터가 삭제되고 복구할 수 없다.

**5. API는 첫 줄에서 인증한다.**

```ts
const user = await getCurrentUser() // 미인증이면 throw
```

**6. 새 라이브러리를 추가하지 않는다.** `package.json`에 이미 있는 것으로 해결한다. 정말 필요하면 팀에 이유를 먼저 설명한다. 비개발자 팀에서 의존성 추가는 빌드 실패와 배포 실패의 가장 흔한 원인이다.

**7. `.env`를 커밋하지 않는다.** `.gitignore`에 이미 들어가 있으니 억지로 추가하지 않으면 된다. 키를 새로 추가하면 `.env.example`에 **키 이름만** 넣고, Amplify 환경변수에도 함께 등록한다(E 담당).

## 6. 커밋과 합병

### 커밋

기능 단위로 커밋한다. "오늘 작업분"을 한 번에 커밋하지 않는다. 코드가 깨졌을 때 되돌릴 지점이 필요하다.

형식은 `<type>: <한국어 설명>`. type은 `feat` `fix` `refactor` `docs` `chore` 중 하나.

```
feat: 일일 미션 목록 화면
fix: 미션 중복 완료 시 500 에러
docs: 미션 개발 문서 갱신
```

**커밋 전에 `npm run build`가 통과하는지 확인한다.** 빌드가 깨진 커밋이 `main`에 들어가면 Amplify 배포가 실패하고 전원이 막힌다.

### 합병

리뷰 없이 본인이 직접 `main`에 머지한다(셀프 머지). **하루에 최소 1회 머지한다. 이틀 이상 묵힌 브랜치는 금지다.** 오래 묵은 브랜치는 머지 시점에 대형 충돌로 돌아오고, 이 팀에서 대형 충돌 해결은 기능 하나를 새로 만드는 것보다 오래 걸린다.

절차는 **항상 `main`을 내 브랜치로 먼저 가져와서** 내 쪽에서 충돌을 해결하는 순서다.

```bash
git checkout main && git pull
git checkout feat/pet && git merge main
```

여기서 충돌을 해결하고 `npm run build`를 확인한 뒤,

```bash
git checkout main && git merge feat/pet && git push
```

**`git rebase`는 쓰지 않는다.** 충돌이 커밋마다 반복돼 되돌리기 어렵다.

### API 응답 형식

5명이 각자 다른 형태로 만들면 화면마다 에러 처리를 다시 써야 한다.

```ts
// 성공
{ data: { ... } }

// 실패
{ error: { code: "MISSION_ALREADY_DONE", message: "이미 완료한 미션입니다" } }
```

HTTP 상태 코드는 `200` `400` `401` `404` `500`만 쓴다. `message`는 화면에 그대로 띄울 한국어 문장으로 쓴다.

## 7. Claude Code를 쓰는 경우

레포에 세션 초기화 대비 문서 체계가 들어 있다. Claude 세션은 길어지면 맥락이 초기화되므로, 문서를 읽는 순서를 정해두었다.

새 세션을 시작하면 이 순서로만 읽힌다.

1. `docs/STATUS.md` — 전체 진행 상황. 이 문서의 "지금 읽어야 할 문서" 표가 이번 세션에 읽을 문서를 지정한다
2. 자기 담당 `docs/dev/<기능>.md`
3. `SPEC.md`의 해당 절만. 전체를 읽지 않는다

`SPEC.md` 절 색인: 1 제약 / 2 유형·종족 / 3 진단 / 4 미션 / 5 키우기 / 6 공유 함수 / 7 챗봇 / 8 커뮤니티 / 9 배너 / 10 아키텍처·AWS / 11 데이터 모델 / 12 제외 기능 / 13 심사 질문

문서를 전부 읽히면 맥락이 컨텍스트를 다 차지해서 정작 코드를 읽을 여유가 없어진다.

**작업을 끝낼 때마다** `docs/dev/<기능>.md`와 `docs/STATUS.md`를 갱신하고 `docs:` 커밋으로 남긴다. 이게 다음 세션의 출발점이 된다.

## 8. 자주 터질 문제

| 증상 | 원인·대처 |
|---|---|
| `Environment variable not found: DATABASE_URL` | `.env`가 없거나 값이 비었다. `cp .env.example .env` 후 값을 채운다 |
| `@prisma/client did not initialize yet` | `npx prisma generate`를 실행한다 |
| 스키마를 고쳤는데 타입이 안 바뀐다 | `npx prisma generate` 후 에디터를 재시작한다 |
| `main`을 pull했더니 DB 오류 | 스키마가 바뀐 것이다. `npx prisma migrate deploy && npx prisma generate` |
| Amplify 배포 실패 | 대부분 ① 빌드가 깨진 커밋 ② Amplify 환경변수 누락. 로컬에서 `npm run build`를 먼저 확인 |
| 머지 충돌이 크게 났다 | 브랜치를 오래 묵힌 것이다. 해결 후 그날부터 매일 머지한다 |
| 재화가 이상하게 들어간다 | `calculateReward()`를 안 통과했거나 두 번 통과했다 |
