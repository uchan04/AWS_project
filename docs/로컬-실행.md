## 끝내는 방법 — 창을 닫는 것으로는 안 된다

**프로세스를 끝내야** Prisma가 커넥션을 반납한다. 한 대가 최대 25개(`CPU × 2 + 1`)를 쥐고,
RDS 앱 몫이 **76개**뿐이다. 2026-08-26에 로컬 2대가 31개를 쥐어 **여유가 −1**이 됐고 조회조차 실패했다.

확인:

```bash
netstat -ano | grep -c ':5432.*ESTABLISHED'   # 0이어야 한다
```

## AWS 자격증명 — `[default]` 프로필이 없으면 업로드가 500이다

`lib/uploads.ts`(커뮤니티 사진)와 미션 사진은 AWS SDK 기본 자격증명 체인을 쓴다.
`~/.aws/credentials`에 **`[default]`가 없고 이름 있는 프로필만** 있으면
`CredentialsProviderError: Could not load credentials from any providers`로 500이 난다.

`.env`에 프로필 이름을 적으면 해결된다(`.env`는 `.gitignore` 대상이다).

```
AWS_PROFILE=<프로필 이름>
```

### 그래도 로컬에서 사진 첨부는 안 된다 (2026-08-26 실측) — **E 확인 필요**

presign은 뚫렸고 **실제 PUT이 IAM에서 막힌다.**

```
POST /api/upload/community/presign   200  { uploadUrl, s3Key, expiresIn }
PUT  <uploadUrl>                     403  AccessDenied
     user/welli-diagnose is not authorized to perform: s3:PutObject
     on resource: arn:aws:s3:::welli-uploads-185236887369/...
```

**코드 문제가 아니다** — presign이 정상 서명을 내주므로 `lib/uploads.ts`는 맞게 동작한다.
로컬 IAM 사용자에게 그 버킷의 `s3:PutObject`가 없는 것이고, **배포본은 Amplify 역할을 쓰므로
이 제약과 무관하다.** 로컬에서 사진 첨부를 시험해야 하면 E에게 권한을 요청한다.

객체는 생성되지 않았다(403이라 쓰기 자체가 일어나지 않았다).

## 로컬에서 안 되는 것 3개

| | 왜 |
|---|---|
| 커뮤니티 사진 **업로드** | 위 IAM. presign까지는 된다 |
| 사진 미션 판정 | `.env`의 `BEDROCK_VISION_MODEL_ID`가 빈 값이다(비전 모델은 코드 폴백이 있지만 업로드가 위와 같은 벽에 막힌다) |
| 실제 Cognito 로그인 | 자체 DB 계정 + 쿠키로 대체한다. `DEV_AUTH_BYPASS`는 `false`로 둔다 |
